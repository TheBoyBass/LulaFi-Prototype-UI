# Architecture rules
- Use semantic foreground tokens for navigation and portal status text independently of decorative brand/status fills, preserving accessible contrast across themes.
- Use the shared Radix Sheet for mobile landing and portal navigation; keep desktop navigation display-hidden below its breakpoint so closed links cannot receive keyboard focus.
- Keep the shared light/dark colour-role definitions in src/lib/colorRoles.ts mirrored by HSL CSS roles; legacy brand utilities alias the interactive role, the wordmark's accent uses that teal interactive role, while brand-main stays reserved for the logo icon, gradients and art, preventing blue branding from changing action meaning.
- Preserve AppContext identity in Vite hot data during live updates so existing consumers and refreshed providers share the same context; keep the missing-provider guard strict.
- Keep the teal action fill constant across themes but give filled teal actions a deeper edge from the stroke roles, and never use teal as text on light surfaces, so action shapes stay identifiable and action text stays readable.
- Never use teal as text in light mode: teal-role text (text-brand, content.interactive/link/selected/accent) resolves to teal-black there; only the lulaFi wordmark "Fi" keeps teal via .text-wordmark.
- Icons are separate from text: they always take the icon role (icon.interactive / text-icon-interactive) and stay the bright action teal in both appearances, so never put a teal text class on an icon element.
- Keep the light/dark/system appearance choice in src/lib/theme.ts as the only writer of the `dark` class on <html>, with AppContext and the landing header subscribing to it, so every surface follows one persisted choice.
- Keep the design system release marker in src/lib/designSystemVersion.ts as the only source for the version shown in the header, footer, version history and AI brief; bump it there (major when a token changes meaning or a rule is reversed, minor for a new documented capability, patch for wording) so pasted briefs always name the standards they encode.
